# Brief — แอปเจ้าหน้าที่ (FondueManager)

> อ่าน [BRIEF.md](BRIEF.md) ก่อนถ้ายังไม่ได้อ่าน

**ไฟล์ที่คุณดูแล: `app/index.html` ไฟล์เดียว** ไม่ต้องแตะไฟล์อื่นเลย

## เป้าหมาย

ทำหน้ารายละเอียดเรื่องแจ้งของแอปให้เหมือนของจริง เพื่อให้คนรีวิวกดลองได้บนเว็บ
โดยไม่ต้องติดตั้งแอปหรือรอ build

## เรื่องที่ต้องเข้าใจก่อน

**แอปเราเป็น React Native — build เป็นเว็บไม่ได้** (พึ่ง native module เยอะมาก
Firebase, notifee, LINE SDK, Google Sign-In) เราจึงไม่ได้เอาโค้ดจริงมารัน
แต่ **วาดหน้าตาขึ้นมาใหม่ด้วย HTML/CSS ให้เหมือนแอป** แล้วใส่ในกรอบมือถือบนเว็บ

เพราะฉะนั้นงานนี้ไม่ใช่ "แก้โค้ดแอป" แต่คือ **"วาดแอปด้วย HTML"** ให้เหมือนที่สุด
คุณคือคนเดียวที่รู้ว่าแอปหน้าตาเป็นยังไงจริงๆ

วิธีที่ง่ายที่สุดคือ **เปิดแอปจริงบนมือถือ วางข้างจอ แล้วไล่ทำให้ตรง**

## สิ่งที่ต้องทำ

### 1. ทำของเดิมให้เหมือนของจริง

เปิด `app/index.html` เทียบกับหน้า detail จริง (`src/screen/.../ProblemOnlyOne.js`)
ตอนนี้ผมทำโครงหยาบไว้ให้ — status bar, app bar, การ์ดข้อมูล, tab bar ล่าง
แต่เดาหน้าตาเอาเกือบทั้งหมด

ที่น่าจะไม่ตรงและควรแก้ก่อน:

- **app bar** — สี ความสูง ตำแหน่งปุ่มย้อนกลับ มีปุ่มขวาไหม
- **การ์ดข้อมูลเรื่องแจ้ง** — ของจริงเรียง label/value แบบไหน มีรูปปกไหม
- **ฟอนต์** — ผมใช้ Noto Sans Thai ถ้าแอปใช้ตัวอื่นบอกได้ เดี๋ยวหาทางฝังให้
- **tab bar ล่าง** — ไอคอนจริงเป็นแบบไหน มีกี่แท็บ ตอนนี้ผมใส่สี่เหลี่ยมแทนไอคอนไว้
- **สีสถานะ** (`.status-pill`) — สีตามสถานะจริง

> ไอคอนจริง export เป็น PNG/SVG มาใส่ในโฟลเดอร์ `app/` ได้เลย
> แต่ **อย่าลิงก์ไป CDN ข้างนอก**

### 2. เติมช่องที่เว้นไว้

ในไฟล์มีกรอบเส้นประ 2 ช่อง (`class="slot"`) ให้แทนที่ด้วย UI จริง
(เป็น HTML นิ่งๆ ก็พอ ไม่ต้องกดทำงานได้)

| ช่อง | ต้องทำ |
| --- | --- |
| ปุ่มปรับสถานะ / ส่งต่อ | ปุ่มด้านล่างหน้า detail ให้เหมือนของจริง |
| Timeline | **สำคัญ** อ่านข้อ 3 |

### 3. จุดที่สำคัญที่สุด — Timeline ตอนเป็นเรื่อง sensitive

นี่คือสิ่งที่เราอยากได้ feedback มากที่สุด

เมื่อเรื่องเป็น sensitive **timeline จะไม่แสดงเป็นข้อความ** แต่ถูกแทนด้วยภาพที่ render
มาพร้อมลายน้ำ (คือส่วนที่แสดงอยู่แล้วหลังกดปลดล็อก)

อยากให้เห็น **ทั้งสองแบบเทียบกัน** — ทำ timeline แบบปกติที่มีข้อความไว้ด้วย
เพื่อให้คนรีวิวเห็นว่าต่างกันยังไง

ถ้าทำได้จะดีมาก: ทำให้ tab bar ล่างหรือปุ่มย้อนกลับ **กดสลับดูอีกเรื่องที่ไม่ sensitive ได้**
จะเห็นความต่างชัดที่สุด (แต่ถ้าไม่ไหวก็ข้ามได้ ทำข้อ 1-2 ให้ดีก่อน)

### 4. เรื่องขนาดจอ

กรอบมือถือตอนนี้กว้าง 390px สูง 800px (ประมาณ iPhone 14) — **อย่าเปลี่ยนขนาด**
เพราะหน้ารวมข้างนอกตั้งให้ตรงกับแท็บ LIFF ไว้พอดี ถ้าเปลี่ยนจะเหลื่อมกัน

ถ้าคิดว่าควรใช้ขนาดอื่นบอกพี่แบงค์ เดี๋ยวแก้ให้ทั้งสองที่พร้อมกัน

### 5. อย่าแตะส่วน sensitive

```html
<div class="rn-card sv-root" id="sensitive-slot"></div>
```

กับ script ท้ายไฟล์ที่เรียก `mountSensitiveFlow()` — สองอย่างนี้ทำงานได้แล้ว
ย้ายตำแหน่งได้ แต่อย่าลบ อย่าแก้ข้างใน

ถ้าอยากปรับหน้าตาส่วน sensitive ให้เข้ากับแอปมากขึ้น เขียน CSS override ทับ
ใน `<style>` ของไฟล์ตัวเองได้ ตัวแปรที่ปรับได้อยู่ใน `shared/sensitive-flow.css`
(`--sv-accent`, `--sv-radius` ฯลฯ) — ในไฟล์มีตัวอย่าง override อยู่แล้วบรรทัดล่างสุด
ที่ทำให้ภาพประกอบเรียง 2 คอลัมน์บนจอมือถือ

## สิ่งที่อยากได้ feedback จากคุณด้วย

ระหว่างทำ ถ้าเจอว่าอะไรใช้งานไม่สมเหตุสมผลบนมือถือ บอกได้เลย โดยเฉพาะ

- ภาพ render กว้าง 1200px มาแสดงบนจอมือถือ อ่านออกไหม ต้อง zoom ไหม
- การใส่ PIN 6 หลักบนมือถือทุกครั้งที่เปิดเรื่อง ในงานภาคสนามจะไหวไหม
- เจ้าหน้าที่ภาคสนามมักใช้มือเดียว ปุ่มปลดล็อกอยู่ตำแหน่งที่กดถึงไหม
