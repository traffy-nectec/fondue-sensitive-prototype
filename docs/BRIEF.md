## นี่คืองานอะไร

เรากำลังทำฟีเจอร์ **Sensitive** — เรื่องแจ้งที่มีข้อมูลส่วนบุคคล (ชื่อ เบอร์โทร ที่อยู่
ใบหน้าในภาพ) จะถูกเข้ารหัสเก็บไว้ ผู้ดูต้องใส่ PIN ปลดล็อกก่อน แล้วระบบจะ render
รายละเอียดออกมาเป็น **ภาพที่ฝังลายน้ำระบุตัวผู้เปิดดู** เพื่อให้ตามรอยได้ถ้าข้อมูลรั่ว

ระบบจริงยังไม่เสร็จ แต่เราอยากให้ทีมได้ **กดลองใช้ก่อน** เพื่อรีวิวว่า flow นี้ใช้งานจริงไหวไหม
ตรงไหนงง ตรงไหนควรแก้ ก่อนที่จะลงแรงทำของจริง

repo นี้คือ prototype นั้น เปิดเป็น GitHub Pages ให้ทุกคนกดลองได้

**https://traffy-nectec.github.io/fondue-sensitive-prototype/**

## สิ่งที่ต้องเข้าใจก่อนเริ่ม

**นี่คือ prototype ไม่ใช่ของจริง** — เป้าหมายคือ *หน้าตาเหมือนของจริงมากที่สุด*
เพื่อให้คนกดลองแล้วรู้สึกเหมือนใช้ของจริง แค่นั้น

เพราะฉะนั้น:

| ✅ ทำ | ❌ ไม่ทำ |
| --- | --- |
| HTML + CSS + JS ธรรมดา | React / Vue / framework อะไรก็ตาม |
| ลอก markup กับ style จากโค้ดจริงของตัวเอง | เขียน UI ใหม่ตามใจ |
| ใช้ข้อมูลจำลองที่เตรียมไว้ให้ | เรียก API จริง / ต่อ backend |
| เปิดแล้วกดใช้ได้เลย | ระบบ login |
| ข้อมูลแต่งขึ้น | ข้อมูลผู้แจ้งจริง เบอร์จริง ชื่อจริง |

repo นี้ **public** ใครก็เห็นได้ — อย่าใส่ token, URL ของ service จริง,
ชื่อ/เบอร์/ที่อยู่ของคนจริง หรือ ticket จริงลงไป

ไม่มี build step ไม่มี `npm install` แก้ไฟล์แล้ว refresh เห็นผลเลย

## เริ่มยังไง

```bash
git clone https://github.com/traffy-nectec/fondue-sensitive-prototype.git
cd fondue-sensitive-prototype
python3 -m http.server 8899
```

เปิด `http://127.0.0.1:8899/` (เปิดไฟล์ตรงๆ ด้วย `file://` ไม่ได้ เพราะใช้ ES module)

จะเห็นหน้าเดียวมี 3 แท็บ — **LIFF ผู้แจ้ง / เว็บเจ้าหน้าที่ / แอปเจ้าหน้าที่**
แต่ละแท็บคือ iframe ของโฟลเดอร์ `liff/`, `web/`, `app/` แยกกันชัดเจน
**คุณแก้แค่โฟลเดอร์ของตัวเอง** ไม่ต้องแตะไฟล์อื่นเลย ไม่ชนกับอีกคนแน่นอน

## ลองใช้ก่อนลงมือ

ไปที่แท็บ **LIFF ผู้แจ้ง** แล้วกดลองให้ครบ flow — นั่นคือหน้าที่ทำเสร็จแล้ว
และเป็นตัวอย่างว่าผลลัพธ์ควรออกมาประมาณไหน

1. กด **ปลดล็อก**
2. ครั้งแรกจะให้ตั้ง PIN 6 หลัก — ตั้งอะไรก็ได้ หรือใช้ `123456`
3. กรอก PIN อีกครั้งเพื่อปลดล็อก
4. จะเห็นภาพรายละเอียดพร้อมลายน้ำ กดปุ่มดูภาพทั้งหมดเพื่อเปิดภาพเต็ม

> ภาพที่เห็นเป็น **ภาพ render จริง** จากเรื่องทดสอบ `2026-62CT43` ลายน้ำเป็นของจริง
> ไม่ใช่ภาพจำลอง

ลองกรอก PIN ผิดดูด้วย จะเห็นจำนวนครั้งที่เหลือ ผิดครบ 5 ครั้งจะถูกล็อก

## ข้อมูลจำลองที่ใช้ร่วมกัน

`shared/sensitive-mock.js` คือแหล่งข้อมูลกลาง ทุกหน้าเรียกฟังก์ชันชุดเดียวกัน
ลำดับการเรียกเหมือน API จริงเป๊ะ ต่างแค่ไม่ได้ยิง HTTP ออกไป

```js
getCredentialStatus()         // เคยตั้ง PIN ไว้หรือยัง
createSensitivePin(pin)       // ตั้ง PIN ครั้งแรก
unlockSensitiveCase(id, pin)  // ปลดล็อก ได้ view token กลับมา
getRenderedContent(id)        // ได้ URL ภาพหลายหน้า + ภาพแนบ
revokeViewSession(token)      // ปิดหน้าจอ คืน session
```

**ห้ามแก้ไฟล์นี้** ถ้าอยากได้ข้อมูลเพิ่มบอกพี่แบงค์ เดี๋ยวเพิ่มให้

`shared/sensitive-flow.js` คือ UI ของ flow (ปุ่มปลดล็อก → ฟอร์ม PIN → แสดงภาพ)
เขียนเป็น JS ธรรมดา ใช้ร่วมกันทั้ง `web/` และ `app/` — เรียกบรรทัดเดียวจบ

```js
mountSensitiveFlow(document.getElementById("sensitive-slot"), {
  ticketId: "2026-6U23NF",
});
```

ส่วนนี้ **ทำงานได้แล้ว ไม่ต้องแตะ** งานของคุณคือทำ *หน้าจอรอบๆ* ให้เหมือนของจริง

## ส่งงานยังไง

แตก branch จาก `main` แล้วเปิด PR

```bash
git checkout -b web/detail-ui     # หรือ app/detail-ui
# แก้ไฟล์ในโฟลเดอร์ของตัวเอง
git add -A && git commit -m "ทำหน้ารายละเอียดฝั่งเว็บให้เหมือนของจริง"
git push -u origin web/detail-ui
```

ก่อนเปิด PR เช็คให้ครบ

- [ ] เปิด `http://127.0.0.1:8899/` แล้วแท็บของตัวเองแสดงถูกต้อง
- [ ] กดปลดล็อก → ตั้ง PIN → เห็นภาพ ครบทุกขั้น
- [ ] Console ไม่มี error สีแดง
- [ ] แท็บ Network ไม่มี request ไปหา API จริง
- [ ] ไม่มีข้อมูลคนจริงหลุดเข้าไป

## ติดตรงไหนถามได้

ถ้าไม่แน่ใจว่า UI ควรออกมาแบบไหน หรือ flow ตรงไหนควรทำยังไง ถามพี่แบงค์ได้เลย
อย่าเดาแล้วทำไปเยอะๆ เพราะเป้าหมายคือ *ให้เหมือนของจริง* ถ้าเดาผิดจะเสียเวลารื้อ
